# mws

Консольная утилита для управления профилями. Профиль — это YAML-файл с полями
`user` и `project`, лежащий в текущей рабочей директории. Имя профиля совпадает
с именем файла: профиль `test` хранится в `test.yaml` в той папке, откуда
запущена команда.

## Сборка

```
go build -o mws .
```

Зависимости: только стандартная библиотека и `gopkg.in/yaml.v3`.

## Команды

```
mws profile create --name=<name> --user=<user> --project=<project>
mws profile get --name=<name>
mws profile list
mws profile delete --name=<name>
mws help
```

Дополнительно: `-h` / `--help` на любом уровне и запуск `mws` без аргументов
тоже показывают справку.

## Примеры

Создание:

```
$ ./mws profile create --name=test --user=example --project=new-project
Профиль test создан (test.yaml)
```

Чтение:

```
$ ./mws profile get --name=test
Профиль:      test
Пользователь: example
Проект:       new-project
```

Список:

```
$ ./mws profile list
ИМЯ      ПОЛЬЗОВАТЕЛЬ  ПРОЕКТ
staging  ivan          billing
test     example       new-project
```

Пустая директория:

```
$ ./mws profile list
В текущей директории нет профилей.
```

Удаление:

```
$ ./mws profile delete --name=test
Профиль test удалён
```

Справка:

```
$ ./mws help
mws — утилита для управления профилями.

Профиль хранится в YAML-файле в текущей директории: профиль test лежит
в файле test.yaml рядом с местом запуска команды.

Использование:
  mws <команда> [аргументы]

Команды:
  profile create --name=<name> --user=<user> --project=<project>
        создать профиль; все три флага обязательны
  profile get --name=<name>
        показать данные профиля
  profile list
        вывести все профили текущей директории
  profile delete --name=<name>
        удалить профиль
  help
        показать эту справку

Пример:
  mws profile create --name=test --user=example --project=new-project
```

### Ошибочные сценарии

Все ошибки печатаются в stderr, код возврата — 1.

```
$ ./mws profile create --name=test --user=example --project=new-project
Ошибка: профиль уже существует: test

$ ./mws profile get --name=missing
Ошибка: профиль не найден: missing

$ ./mws profile delete --name=missing
Ошибка: профиль не найден: missing

$ ./mws profile create --name=test
Ошибка: не указаны обязательные флаги: --user, --project

$ ./mws profile create --name=../escape --user=a --project=b
Ошибка: имя профиля "../escape" не должно содержать разделители пути
```

## Формат хранения

`test.yaml`:

```yaml
user: example
project: new-project
```

Имя профиля внутри файла не хранится — оно определяется именем файла.

## Допущения

ТЗ оставляет несколько мест на усмотрение разработчика, вот как они решены:

1. Расширение файла профиля — `.yaml`.
2. `create` для уже существующего имени — ошибка «профиль уже существует», без
   тихой перезаписи. Команды обновления профиля в ТЗ нет, поэтому она не
   реализована.
3. `get` и `delete` для несуществующего профиля — понятное сообщение в stderr и
   ненулевой код возврата.
4. Имя профиля валидируется: непустое, без `/` и `\`, без `..`, не начинается с
   точки. Это прямая реализация требования работать только в текущей папке —
   иначе через имя файла можно было бы выйти за её пределы.
5. `list` без профилей печатает явное сообщение. Иначе выводит таблицу
   (имя / пользователь / проект), отсортированную по имени для предсказуемости.
   `.yaml`-файлы, которые не разбираются в структуру профиля, а также файлы, где
   оба поля пусты (то есть посторонние YAML рядом с профилями), молча
   пропускаются — из-за чужого файла в папке команда падать не должна.
6. `get` печатает поля в читаемом виде, а не сырой YAML.
7. Файлы профилей создаются с правами `0644`.

## Структура

```
main.go                      разбор верхнеуровневых команд
internal/cli/                слой CLI: флаги, вывод, сообщения об ошибках

internal/profile/store.go    Create/Get/List/Delete поверх YAML-файлов
```
